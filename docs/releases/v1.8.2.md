# OpenPAVE v1.8.2 — Body-side safety

**Date:** 2026-10-07 · **Tag:** `v1.8.2`

A patch release on [`v1.8.1`](v1.8.1.md): safety fixes for a body that is left moving when its brain goes
away. No new feature surface; the seam, the `{action, params}` contract and the registries are unchanged.

> This note was added afterwards, in [`v1.8.3`](v1.8.3.md) — the `v1.8.2` tag itself does not contain it.
> The tag message carries the same facts. The documentation refresh and the validation-matrix re-grade
> that were prepared at the same time are in `v1.8.3`, not here.

## Why

Until now every STOP guarantee lived on the **brain**. A brain stopped with `kill`, an SSH session that
dropped, a crashed or `kill -9`ed brain, or a lost network link all left a body that had been told to
`trot` marching with nobody to stop it — a locomotion verb persists until a `stop` arrives.

## Safety fixes

- **STOP on `SIGTERM` and `SIGHUP`, not only `Ctrl+C`.** Python only runs cleanup for `SIGINT`; the
  other two killed `run_live` / `run_inference` outright. `pave_runtime/shutdown.py` now turns all three
  into a clean shutdown whose `finally` STOPs the body (exit code `128 + signal`). A second signal while
  the STOP is in flight is ignored so it cannot interrupt it.
- **An unconfirmed STOP is loud.** If the final STOP does not complete — at the end of `run_live`, or at
  the end of an interrupted `--allow-motion` lease — the driver exits `5` (safety-critical) instead of
  passing silently. The `--allow-motion` lease now also covers the motion send itself, so a signal that
  lands mid-send still ends in a STOP.
- **Body-side dead-man lease** (`pave_runtime/lease.py`, shared by `raw_zenoh` and `device_connect`).
  Every `trot` / `move` the body accepts carries a lease (`BODY_MOTION_TTL_S`, default **5 s**); if the
  brain does not renew it, **the body STOPs itself**. There is no brain-supplied TTL, so a buggy brain
  cannot ask for a longer one. Renewal is re-sending the same motion — the lease layer only extends the
  deadline and does not call the adapter again, so there is no gait hiccup. `run_live` renews every
  `--lease-renew-seconds` (default 2 s) from its own task; renewals and STOPs are serialized so a renewal
  can never land after a STOP and restart the body. `run_inference --allow-motion` renews during its hold.
- **A body process being shut down leaves its actuator stopped.** `seam_cli.py serve` sends `stop` to its
  adapter on `SIGTERM` / `SIGHUP` / `Ctrl+C` (an unconfirmed stop exits `5`).
- The `raw_zenoh` `send` now closes its session when cancelled mid-send.

## Behaviour changes

- **A one-shot `seam_cli.py send trot` no longer marks time until a `stop`.** It is never renewed, so the
  body stops it after about 5 s. Use `run_live.py`, or `run_inference.py --allow-motion --motion-hold-seconds N`,
  which renew. (`v1.8.3` adds a note to the three runbooks that send `trot` then `stop`; they still work as written.)
- `run_live` / `run_inference` / `seam_cli serve` now exit `128 + signal` when ended by a signal.

## Verification

- **193 unit tests** pass (up from 143), including tests that send real `SIGINT` / `SIGTERM` / `SIGHUP` to
  the real CLI entry points. Those tests fail against the previous scripts. The concurrency tests were
  mutation-checked: removing the send lock or the post-STOP guard turns them red.
- **Real `raw_zenoh` with a mock body:** 14 s of motion on a 5 s lease produced exactly one `TROT` and no
  expiry; after the brain was `kill -9`ed mid-motion the body stopped itself in **4.2 s** on one host and
  **3.0 s** from a DGX brain to a Raspberry Pi 5 over the LAN, and was not restarted. Expect 3–5 s
  (the last renewal lands up to 2 s before the kill, plus the body's own stop time).

## Not verified

- **No physical actuator and not the real dog.** The Raspberry Pi 5 had no servo attached, so the
  cross-host run used a dry-run servo (real network and real camera frames, no actuation). The dead-man
  test on a real PuppyPi is still to be done.
- **`device_connect`:** the lease logic is tested through `guarded_dispatch` and the `raw_zenoh` backend,
  but `dc_seam.serve()`'s own wiring has no test and has not run against a live Device Connect runtime.
- **Known limit:** the lease lives in the body *process*. If that process itself crashes or is `kill -9`ed,
  a controller that runs separately (PuppyPi's `puppy_control`, in its own container) keeps running.
  Closing that needs enforcement in the bridge / controller below the body process.

## Known issues found after release (fixed in [`v1.8.3`](v1.8.3.md))

- **A shutdown signal could be lost on Python before 3.12.** `run_live` bounded its observation and
  inference calls with `asyncio.wait_for`, which on those interpreters returns the inner result instead of
  raising `CancelledError` when the cancellation lands in the same event-loop iteration in which the inner
  call finishes (measured on Python 3.9). The signal was then ignored and, because the shutdown path
  ignores further signals, the loop could only be ended with `SIGKILL` — and while it ran it kept renewing
  the body's lease. The window is small (microseconds against a ~1 s inference) and **Python 3.12, as on the
  DGX Spark, is not affected**; it was found as a flaky test under CPU load (about 1 in 25 runs on 3.9).
- **A STOP could wait behind a renewal that was hanging on the network**, up to the send timeout (5 s),
  because renewals and STOPs share one lock. The body's own lease still bounded the exposure.

## Compatibility

Additive apart from the behaviour changes above. No change to the seam plugin interface, the capability
contract, the adapters' public methods, or the PuppyPi paths. Brains from `v1.8.0` / `v1.8.1` still work
against a `v1.8.2` body; they simply do not renew motions, so those motions stop after the lease.
