# OpenPAVE v1.7.0 — Inference / Application Runtime Plugin

**Date:** 2026-09-03 · **Tag:** `v1.7.0`

The fourth dimension becomes a plugin. v1.7.0 adds a **headless inference/application runtime**
boundary on the brain side — the same registry pattern as the seam transport — so the application
layer (gesture control today; VLA policy, planner, agent, or an external project tomorrow) is a
registered backend rather than a fork. This is the headless foundation; the live loop and UI-as-observer
work is scheduled for v1.8.

Built on [`v1.6.0`](v1.6.0.md). **Purely additive** — the validated baseline gesture path and the
seam transport plugin are unchanged.

## Layered pipeline (not one big plugin)

```text
Observation → InferenceRuntime → ApplicationRuntime → capability validation → dispatch → Body
              (model result only)  (ActionProposal)     (normalize + safety)   (v1.7: mock only)
```

Responsibilities stay separate on purpose: `InferenceRuntime.infer()` returns only the **model
result**; `ApplicationRuntime.decide()` turns it into an **unexecuted `ActionProposal`**; the model
call, the application semantics, and action safety are never merged into a single oversized plugin.

## Highlights

- **`create_inference_runtime(name)`** registry + `InferenceRuntime` protocol
  (`pave_runtime/inference.py`), mirroring `create_seam_transport` — lazy imports, zero core deps.
- **`vllm_openai` backend** (`pave_runtime/inference_backends/vllm_openai.py`): calls an
  OpenAI-compatible vLLM `/chat/completions` endpoint with a static JPEG/PNG observation.
- **`create_application_runtime(name)`** + **`gesture_commander`** (`pave_runtime/application.py`):
  parses the model text into a `STOP`/`TROT` capability action, with a **safety fallback to `stop`**
  on ambiguous output.
- **Headless driver** `scripts/run_inference.py`: one observation → inference → application →
  capability normalize → dispatch, emitting a three-segment latency JSON. Reuses the single-source
  `pave_runtime.seam.dispatch`.
- **Spec** [`docs/v1.7_spec.md`](../v1.7_spec.md) and **16 unit tests** (runtime registry + vLLM
  backend, HTTP mocked).
- **Config**: v1.7 inference/application profile added to `configs/mock.env`
  (`INFERENCE_RUNTIME` / `APPLICATION_RUNTIME` / `PROMPT_PRESET`).

## Real-hardware validation (2026-09-03)

Validated on **two real Arm brains** (DGX Spark and Radxa O6) with a **real RPi5 camera** as the
observation source:

- **DGX Spark brain** — RPi5 `/dev/video0` frame (640×480 JPEG) → DGX
  `llava-hf/llava-v1.6-mistral-7b-hf` (`INFERENCE_RUNTIME=vllm_openai`, HTTP 200, ~1187 ms) →
  `gesture_commander` proposal → capability normalize → **dispatch `completed`** to the mock adapter.
- **Radxa O6 brain (Armv9, `orion-o6`)** — ran the runtime plugin's brain duties (the
  inference-runtime **client**, the application, and dispatch) on Armv9. Because `vllm_openai` is an
  OpenAI-compatible client and Radxa has **no local model server yet**, `INFERENCE_API_BASE` pointed
  **cross-host** at the DGX vLLM (HTTP 200, ~1000 ms); same frame → `gesture_commander` `stop` →
  **dispatch `completed`** to mock. This validates plugin portability to a second Arm brain and the
  inference-runtime-as-client design — **not** local model serving on Radxa, which is v1.8 (a second,
  local inference backend such as Ollama / llama.cpp).
- In both, the model saw a room with no clear gesture and returned the prompt's safe default `STOP`;
  the application produced `stop` (no fallback needed), confirming the full plugin chain end to end.

## Scope decisions

- **Dispatch is mock-only in v1.7** (`run_inference.py` refuses non-mock adapters). Driving a real
  robot from this path is v1.8, together with the live loop.
- **Safety/capability validation is distributed** for now (`gesture_commander` fallback +
  `normalize_action_payload` + `seam.dispatch` capability check). Consolidating it into a dedicated
  fixed core validation layer is a v1.8 refactor.

## Deferred to v1.8

`ObservationSource` as a plugin, the image data plane, multi-endpoint routing
(`SENSOR_TARGET` / `ACTION_TARGET`), the live control loop, a second inference backend, and reworking
the UI into a pure observer.

## Compatibility

Additive only. No change to the runtime baseline, the seam plugin, the robot adapters, or the
validated matrix carried forward from `v1.5.0-seam` / `v1.6.0`. The new matrix row records the
real-DGX inference-plugin validation.
