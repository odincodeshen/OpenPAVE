# OpenPAVE v1.8.0 — Live Body (inference → seam → real robot)

**Date:** 2026-09-03 · **Tag:** `v1.8.0`

v1.8.0 connects the v1.7 headless inference/application pipeline to a **real body over the seam**, and
adds a **persistent live loop** — the full Physical AI loop, on real hardware:

```text
camera frame (data plane) → ObservationSource → InferenceRuntime → ApplicationRuntime
                          → capability action → seam (control plane) → robot actuator
```

Image bytes stay on the sensor data plane; the seam carries only the resulting low-rate action. Built
on [`v1.7.0`](v1.7.0.md); the single-shot mock path and the seam/baseline are unchanged.

## Highlights

- **ObservationSource plugin** — `create_observation_source` with `file` and `http_mjpeg` backends;
  `run_inference.py --input-url` captures one HTTP/MJPEG frame (e.g. a PuppyPi camera).
- **Real-body dispatch** — `run_inference.py --seam <transport>` sends the validated action to a body
  over the seam (the body-side adapter, e.g. `puppypi_bridge`, runs on the robot).
- **Motion safety gate** — single-shot `--seam` **blocks locomotion** (`trot`/`move`) unless
  `--allow-motion`, which then holds the motion for a bounded window and issues an **automatic STOP**
  (including on `Ctrl+C`); `stop`/`home`/`estop` always pass.
- **Outcome → exit code** — the payload carries an explicit `outcome`, and the process exits `0` ok /
  `3` dispatch failed / `4` blocked / `5` safety-critical (a STOP did not complete).
- **Explicit target** — `--action-target` (env `ACTION_TARGET`) selects the body; `device_connect`
  **rejects an ambiguous multi-body discovery** instead of driving the first one found.
- **Live loop** — `scripts/run_live.py` runs observe → infer → decide → **confirm** → dispatch
  continuously, owning the motion lifecycle: a motion verb is dispatched only after **N consecutive
  confirmations** in a window (`TROT_CONFIRMATIONS` / `TROT_CONFIRMATION_WINDOW_MS`), dispatch is
  edge-triggered, a **stall watchdog** auto-STOPs, and shutdown always STOPs the body. Each tick is
  paced and emits a compact JSONL record.
- **Tests** — observation sources, seam dispatch + the gate/outcome/target, and the live loop, all
  with injected fakes (no zenoh, Device Connect, model, or robot). Full suite **123 tests**.

## Real-hardware validation (2026-09-03)

DGX Spark brain → `raw_zenoh` seam → real PuppyPi (`puppypi_bridge`), RPi5 as the camera:

- **Single-shot** — RPi5 frame → DGX `vllm_openai` (~1 s) → `gesture_commander` → `--seam raw_zenoh` →
  real PuppyPi, `path=bridge` (STOP ~515 ms, TROT ~1013 ms).
- **Live loop** — RPi5 served as a JPEG snapshot source. Real vLLM: room → `stop` → dog stop,
  edge-triggered no-ops after. Forced `TROT` (mock runtime): confirmed on the 2nd frame → dog trots
  (`path=bridge` ~1019 ms) → bounded run → **automatic STOP**. A vLLM outage during a run confirmed the
  loop fails safe (no spurious dispatch) and exposed a busy-loop bug (a failing tick skipped pacing),
  now fixed.

## Safety posture

Real-body motion is gated and validated only with an operator watching. Camera-driven runs default to
dry-run / mock dispatch; motion requires `--allow-motion` (single-shot) or multi-observation
confirmation (the loop). All findings from the v1.8 live-body review (motion confirmation, motion
lease + auto-STOP, outcome propagation, target selection, mutual-exclusion, tests) are addressed. See
[v1.8 Live Body](../v1.8-live-body.md).

## Deferred (optimizations)

A persistent brain-side seam session (to avoid the per-call discovery settle) and a persistent MJPEG
stream reader (instead of per-tick re-capture) are follow-ups; correctness does not depend on them.

## Compatibility

Additive. No change to the runtime baseline, the seam plugin, the robot adapters, or the validated
matrix carried forward from `v1.5.0-seam` / `v1.6.0` / `v1.7.0`. In-process `--dispatch` stays
mock-only.
