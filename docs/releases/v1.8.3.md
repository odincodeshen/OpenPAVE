# OpenPAVE v1.8.3 — Cancellation-safe shutdown, and an honest re-grade

**Date:** 2026-10-07 · **Tag:** `v1.8.3`

A patch release on [`v1.8.2`](v1.8.2.md) with two small safety fixes in `run_live` found by re-auditing
`v1.8.2`, plus a documentation refresh. It re-grades the validation matrix against stricter definitions,
brings the documents that had gone stale in line with what has been built, and adds the release note for
`v1.8.2` (whose tag was published without one). No interface changed.

## Safety fixes

- **A shutdown signal can no longer be lost.** `run_live` now bounds its observation / inference calls with
  `pave_runtime.shutdown.bounded`, built on `asyncio.wait`, instead of `asyncio.wait_for`. Before Python 3.12,
  `wait_for` could swallow a cancellation that arrived in the same event-loop iteration in which the inner
  call finished — so `SIGTERM` / `SIGHUP` / `Ctrl+C` could be ignored and the loop keep running (see the
  known issues in the `v1.8.2` note). The DGX Spark (Python 3.12) was not affected; Python 3.9 was, in about
  40% of deliberately aligned cancels and in about 1 of 25 runs of the existing cancellation test under CPU load.
- **A STOP now preempts a renewal that is hanging on the network** instead of waiting behind it (up to the
  5 s send timeout). The preempted renewal is cancelled before the STOP is sent, so ordering is preserved: a
  renewal is never delivered after a STOP.

## Why re-grade

The matrix called several rows "Validated" on the strength of a single short run, or of a run in which part
of the chain was mocked or forced — for example a `TROT` produced by a mock runtime rather than by a real
gesture. Several other documents still described the project as it was at v1.0 (inference "pluginization
is roadmap", a "Validated Today" list that stopped at the baseline, a Jetson Thor claim with no evidence in
the repository). A release should not ship a grade stronger than its evidence.

## Validation matrix re-graded

`docs/validation-matrix.md` now defines four statuses and an evidence class:

- **Candidate → Experimental → Supported → Validated.** Supported means the combination was run through its
  complete flow once on its real hardware; Validated additionally needs a reproducible runbook, structured
  benchmark results, recorded artifacts, documented limitations, and at least 10 runs of every declared
  action (a manipulation combination: at least 10 physical rollouts with the full success rate reported).
- **Evidence class `hardware` / `software`** says whether a real device was in the evidence run. A `software`
  Validated is a statement about software only.

The earlier labels (`Baseline`, `Partial`, a looser `Validated`) were mapped onto these; a re-grade table in
the matrix records, per row, what changed and what it still needs.

**Net effect:** several rows went **down** — five rows that were "Validated" (the v1.7 headless runs, the
v1.8 single-shot and live-loop runs on the real dog, and `gpio_servo`) are now Experimental, as is the
`/pave` console path; Jetson Thor and the unevidenced Arm-node rows are Candidate. Seven rows went **up** to
Supported: the PuppyPi seam rows (DGX and Radxa O6, both transports) and the RPi 5 camera rows, which were
reproduced from their runbooks on clean checkouts, and the software-only `mock_arm` row. **Nothing is Validated on real hardware yet** — the
only Validated row is the software-only control-path benchmark. A row was also added for the cross-host
dead-man-lease run (a dry-run servo: real network and camera, no actuation).

## Other documents brought up to date

- `docs/openpave-platform-spec.md` — the four-dimension table, the config recipes that exist, the seam
  section (incl. the body-side lease and that the seam carries low-rate semantic actions), the current
  state, and a roadmap that no longer lists finished items.
- `docs/further-work.md` — adds the v1.5 – v1.8.2 work, ticks the items that are done, and adds the lease
  limits to the known limitations.
- `docs/latency-model.md` — the inference segment had been measured (about 1.0–1.2 s per frame) but was
  listed as not measured.
- `docs/demo-catalog.md` — its status words now defer to the matrix; the baseline PuppyPi + DGX demo is
  Supported rather than "Validated".
- `README.md` / `README_cn.md` — the status summaries use the new vocabulary.
- The three runbooks that send a one-shot `trot` then `stop` carry a note that, since `v1.8.2`, a motion
  the brain does not renew is stopped by the body after about 5 s.
- `docs/releases/v1.8.2.md` — the release note for the safety release.

Not changed on purpose: the roadmap lists only next steps backed by what exists; plans that are not yet
agreed for publication are not in these documents.

## Verification

- **200 unit tests** pass (193 in `v1.8.2`), from a clean checkout of the tag on Python 3.9 (Mac) and 3.12
  (DGX Spark). Both fixes have regression tests that were **mutation-checked** — reverting the fix turns the
  test red: `bounded()` replaced by `wait_for` loses 34 of 84 aligned cancels; removing the preemption makes
  a STOP wait 2.3 s behind a 3 s hanging renewal.
- The test that exposed the first problem, `test_cancellation_mid_motion_still_stops_the_body`, failed once in
  25 runs under CPU load before the fix and **0 of 60** after it.
- The touched documents were audited against the code: every relative link resolves, every CLI flag and
  environment variable they name exists, the stated defaults (TTL 5 s, renewal 2 s, hold 3.0 s, exit codes)
  match the code, and the matrix table is internally consistent (22 rows; statuses and evidence classes valid;
  no Candidate row still describing itself as validated).

**Still not verified:** a physical actuator and the real dog (the Raspberry Pi 5 used for the cross-host run
had no servo, and its sshd was unreachable when the final re-audit ran, so the suite was not re-run on its
Python 3.13); `device_connect`'s `serve()` wiring against a live runtime.

## Compatibility

No interface changes. `run_live` behaves the same except in the two situations above. Older release notes
(`v1.7.0` – `v1.8.1`) use "validated" in the earlier, looser sense; the matrix holds the current grading.
