# OpenPAVE v1.5.0-seam — Seam Transport Plugin

**Date:** 2026-09-02 · **Branch:** `feat/seam-transport` · **Tag:** `v1.5.0-seam`

This release turns the brain↔body **seam into a plugin**: one capability contract, swappable
transports, validated end to end with real brains driving real robots and sensors. It also lands the
four-dimension config model, reproduction tooling, a latency model, and a single-source refactor —
the pre-cleanup milestone before merging to `main`.

## Highlights

- **Seam is now a plugin** — pick the transport with one env var; body and brain code are unchanged.
- **Real-brain validation matrix** — DGX Spark and Radxa O6 (Armv9, first validation) each drove the
  real PuppyPi (actuator) and RPi5 USB camera (sensor) over **both** transports.
- **Turnkey reproduction** — four-dimension config recipes + a one-command launcher + a deploy script
  + pinned requirements + a runbook.
- **Latency model** — measured three-segment breakdown; the seam itself is sub-millisecond.

## What's new

### Seam transport plugin (`pave_runtime.seam`)
- `dispatch(adapter, action, params)` — the single-source, transport-agnostic body endpoint
  (`{action, params}` in, capability state out).
- `SeamTransport` protocol (`serve` / `send`); fleet-level features stay backend-specific.
- `create_seam_transport(name)` registry — lazy backend import, **zero core dependencies**.
- Backends:
  - `raw_zenoh` — zenoh-python, capability JSON over pub/sub (`ZENOH_LISTEN` / `ZENOH_CONNECT`).
  - `device_connect` — Arm Device Connect: one labeled `@rpc` per capability, D2D discovery over
    zenoh multicast presence (no server, no registry).
- `scripts/seam_cli.py` — unified body/brain; the adapter import is lazy, so **a brain needs no
  `control_daemon`** (deploy is ~9 KB of `pave_runtime` + the transport lib).

### Real-brain validation matrix
Same `seam_cli.py` and `puppypi_bridge`, only `SEAM_TRANSPORT` and the brain host change:

| Brain | Body | `raw_zenoh` | `device_connect` |
| --- | --- | --- | --- |
| DGX Spark | PuppyPi (actuator) | home 516 / trot 1015 / stop 515 ms | 511 / 1013 / 514 ms |
| Radxa O6 | PuppyPi (actuator) | 512 / 1013 / 514 ms | 511 / 1014 / 514 ms |
| DGX Spark | RPi5 camera (sensor) | `get_image` ok (jpeg ~98 KB) | ok (~97 KB) |
| Radxa O6 | RPi5 camera (sensor) | ok (~99 KB) | ok (~98.7 KB) |

All actuator actions `path=bridge`, camera-confirmed. Cross-host `device_connect` D2D discovery works
on the LAN with zero infrastructure. See `docs/validation-matrix.md`.

### Four-dimension config recipes + tooling
- `configs/{dgx,radxa}-{puppypi,camera}.env` — a recipe pins brain × body × transport × inference.
- `scripts/seam_run.sh` — role-aware launcher; sources a recipe and derives the transport wire env.
- `scripts/deploy_seam.sh` — deploy the seam bundle to any brain (+ optional pinned-deps install).
- `requirements-seam.txt` / `requirements-seam-camera.txt` — pinned (zenoh 1.9.0, device-connect
  0.2.5, opencv-python-headless 5.0.0.93).
- `docs/seam-validation-runbook.md` and README "Reproduce the Seam Validation".

### Performance
- `docs/latency-model.md` + `scripts/seam_bench.py` — three segments (inference / seam / execution).
- **Steady-state seam wire ~0.58 ms p50 / 0.65 ms p95**; a one-time **~0.5 s** `raw_zenoh` session
  setup (per-call in the current CLI, once per persistent session); execution is bridge-dominated
  (~514 ms home/stop, ~1013 ms trot). Inference (VLM) segment is future work.

### Refactor — single source
- All four seam experiments (`neutral-seam`, `device-connect`, `capability-mve`, `camera-mve`) now
  import `dispatch` from `pave_runtime.seam` instead of carrying their own copy (net −62 lines).

## Using it

```bash
# 1. deps (each host's venv)
<venv>/bin/pip install -r requirements-seam.txt          # brain + body
<venv>/bin/pip install -r requirements-seam-camera.txt   # camera sensor body only
# 2. deploy the seam bundle to a brain
scripts/deploy_seam.sh odin@<brain> '$HOME/openpave-seam' '$HOME/.venv-zenoh/bin/python'
# 3. body, then drive from the brain (swap SEAM_TRANSPORT to change transport)
scripts/seam_run.sh configs/dgx-puppypi.env body
scripts/seam_run.sh configs/dgx-puppypi.env brain send home
```

## Compatibility

Additive and experimental — the validated baseline runtime path is unchanged. The seam plugin,
recipes, and tooling are new; nothing in the existing runtime was removed or altered in a breaking way.

## Known limitations

- The per-call `raw_zenoh` session setup (~0.5 s discovery settle) is comparable to a fast action's
  execution; use a **persistent brain session** for high-rate control.
- The camera **data plane** (frame bytes) travels outside the seam (see `experiments/camera-mve/`);
  the seam carries the `get_image` control-plane metadata only.
- The **inference** latency segment is not yet measured in-seam.
- The two ROS-node experiments (`capability-mve`, `camera-mve`) need a ROS 2 host for full runtime
  tests; their converged dispatch is covered by the shared unit tests and a data-plane invariant check.
